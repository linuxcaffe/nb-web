# NbWeb-hledger

Plain-text accounting for nb-web — Canadian domain knowledge, chart of accounts wizard, and inline journal entry on top of [hledger](https://hledger.org/).

---

## Activation

Add an `hledger:` block to your notebook's own config dotfile (`.{notebook}.md` — the same file that already carries `title`, `nav`, `tabs`, etc.) to activate the plugin for that notebook:

```yaml
---
type: dotfile
title: mynotebook config
...
hledger:
  journal: accounting/journals/main.journal
  commodity: CAD
  fiscal_year_start: 01-01
  province: "ON"
  entity: sales
  business_number: ""
  hst_number: ""
---
```

| Field | Required | Description |
|-------|----------|-------------|
| `journal` | yes | Path to your main journal file, relative to the notebook root |
| `province` | yes | Two-letter province code — drives tax account structure |
| `commodity` | no | Default commodity symbol (default: `CAD`) |
| `entity` | no | `personal`, `smallbiz`, or `sales` |

After adding the block, the notebook will show the hledger icon and activate the plugin panel.

*(A standalone `.nb-hledger.json` anchor file is also still recognized for backward compatibility, but no real notebook uses it — the `hledger:` block above is the current convention.)*

## Note types

| Type | Frontmatter | Purpose |
|------|-------------|---------|
| `account` | `hledger_account`, `cra_label`, `cra_line_t1`, `cra_line_t2125` | One note per leaf account — docs, tax mapping, opening balance |
| `template` | `hledger_template` | Recurring transaction templates (mortgage, payroll, etc.) |
| `period` | `hledger_period` | Month-end or year-end checklist |
| `report` | `hledger_report` | Curated hledger report queries |
| `item` | (shop-domain fields — see nbweb-quartz help) | A resale-shop item listing (Sales domain). Cost/sale tracking lives in its annotation, not here — see "Item cost & sale tracking" below. |

### Account note frontmatter

```yaml
---
title: Chequing Account
type: account
hledger_account: Assets:Cash:Chequing
cra_label: Bank accounts
cra_line_t1: ""
---
```

A **platform** account note (`Income:Sales:<Platform>`, generated by the Sales domain wizard) carries extra fields describing that platform's tax-collection behaviour:

```yaml
---
title: "Income:Sales:Etsy"
type: account
hledger_account: "Income:Sales:Etsy"
platform_category: marketplace
tax_collection:
  gst_hst: collects-all      # does this platform collect & remit GST/HST for you?
reporting:
  cra_seller_info_return: true
payout:
  clearing_account: "Assets:Payment:Stripe"
credential_ref: ""            # pointer to an encrypted note holding login info — never the secret itself
last_verified: 2026-07-14
source_url: "https://www.etsy.com/legal/taxes/canada/"
---
```

Which platform-tax fact matters day to day: whether the platform collects GST/HST *for* you changes which posting template applies when you record a sale — see "Item cost & sale tracking" below.

## Chart of Accounts wizard

The plugin panel includes a **Chart of Accounts** wizard that generates a complete `accounts.journal` from scratch.

1. Choose a **domain** — Personal Finance, Small Business, Service (Independent Contractor), or **Sales (Resale/Shop)**
2. Choose your **province** — drives which tax accounts are created
3. Select **options** — for Sales: check the platforms you actually sell on (Etsy, eBay, Facebook Marketplace all have seeded defaults — you don't need to answer "does this collect tax for me," the wizard already knows); type in an "Other platform" name for anything not listed; plus in-person/wholesale/consignment/etc.
4. Click **Preview** to see the account list before writing
5. Click **Generate** to write `accounts.journal` to your notebook, then **Create account notes**

Your domain and option selections are remembered per notebook — reopening Setup later restores what you had, instead of resetting to defaults every time.

If your main journal already exists, you'll get an `include` directive to paste in.

The wizard creates one `account` note per leaf account — each note is a stub with frontmatter and a one-line description. Fill in the details as you use the accounts.

## Item cost & sale tracking (Sales domain)

**Cost and sale price never go in the item note itself** — only the public asking `price:` lives there, in frontmatter, published as normal. Everything financial (what you paid, what it sold for, fees, tax) lives in the item's **annotation** — the hidden `.{item}.md.annotations.md` sidecar every note already has — as `​```ledger​```` blocks:

```ledger
; --- acquired ---
2026-03-15 Value Village — silk scarf
    Assets:Inventory              15.00 CAD
    Assets:Bank:Business:Chequing

; --- sold ---
2026-04-20 Customer — Etsy  ; tax:platform-collected
    Assets:Payment:Stripe         86.00 CAD
    Income:Sales:Etsy            -85.00 CAD
    Income:Shipping:Recovered     -8.00 CAD
    Expenses:Platform:Etsy         7.00 CAD
    Expenses:COGS                 15.00 CAD
    Assets:Inventory             -15.00 CAD
```

Why this is safe: annotation content is never published, by construction — the Quartz site-build simply never sees dotfiles at all, not because of an access rule that could be misconfigured.

**Three action buttons appear on an item's header** once you're on the Sales domain:
- **✅ Sold** — one click, flips `status: sold`. Doesn't touch the annotation — record the actual sale yourself using the template above.
- **📊 Summary** — reads the item's own annotation and shows bought/sold/fees/net at a glance.
- **📝 Fields** — fill in *any* field your `items/.items.md` schema declares, required or optional, even ones this item doesn't have yet. See nbweb-quartz's help for the schema itself.

A **"sold, no sale recorded"** warning appears on the header if `status: sold` but no matching sale transaction exists yet in the annotation — a nudge, not a blocker.

**Regenerating the real journal from item annotations** is a separate step, not automatic: run `pfinds:.tools/gen-items-journal.py` (or whatever notebook's `.tools/` holds your own copy of it) to compile every item's annotation `ledger` blocks into the journal your `hl` reports actually read.

## Journal file preview

`.journal`, `.ledger`, and `.hledger` files open with syntax highlighting in the preview pane:

| Token | Highlighted as |
|-------|---------------|
| Transaction dates (`2024/01/01`) | constant |
| Account names (indented postings) | string |
| Amounts | variable |
| Comments (`;`) | muted |
| Directives (`account`, `payee`, `include`, …) | keyword |
| Tags (`:tagname:`) | tag |

### Clickable `include` links

`include` directives in a journal file are rendered as clickable links — click the path to open that file directly in the preview pane.

```
include accounts.journal        ← click to open
include ./subdir/payees.journal ← click to open
```

Links are resolved relative to the current journal file's location. A dotted underline means the file is found in the notebook; a strikethrough means it couldn't be resolved (e.g. an absolute path outside the notebook tree).

This makes it easy to browse a multi-file journal — follow the include chain without leaving the app.

## Inline journal entry

In any hledger codeblock, click **[+ Add]** to open the inline entry form:

- **Date** — defaults to today
- **Description** — payee / narration
- **Postings** — account (with autocomplete from your chart), amount, optional comment
- **[Cancel] [Save]** — Save appends the transaction to the journal

Account autocomplete is sourced from `hledger accounts --flat` against your configured journal — it respects your full include chain.

## CRA tax mapping

Account notes support CRA line number fields for tax return prep:

| Field | Return | Example |
|-------|--------|---------|
| `cra_line_t1` | T1 personal | `line_15000` |
| `cra_line_t2125` | T2125 self-employment | `line_8860` |

These fields are populated by the CoA wizard based on the domain pack's built-in mappings. You can edit them directly in the note frontmatter.

When accounts have `cra_line_t1` values, the **T1 report** (under Reports) groups balances by return line — useful for tax prep without a bookkeeper.

## Chart codeblocks

Add a `` ```chart ``` `` fence anywhere in a note to render an interactive financial chart:

````markdown
```chart
cashflow thisyear
```
````

The fence body is `<report> [period] [depth:N]`.

### Report types

| Report | Default view | Description |
|--------|-------------|-------------|
| `cashflow` | bar + line | Monthly income vs expenses with cumulative net change |
| `networth` | line | Assets, liabilities, and net worth over time |
| `expenses` | stacked bar | Monthly expense breakdown by category |
| `expenses-pie` | doughnut | Expense share by category for the period |
| `assets-pie` | doughnut | Asset allocation snapshot |
| `income-pie` | doughnut | Income sources for the period |

### Options

- **Period** — any hledger period expression: `thismonth`, `thisyear`, `lastyear`, `last6months`, `2025`, `2025-01..2025-06`, …
- **`depth:N`** — account depth for category breakdown (default `2`). Higher values show more granular sub-categories.
- **`-p period`** — alternative flag syntax, e.g. `cashflow -p lastyear`

### Header controls

Every chart block has an interactive header:

- **▾ / ▸** — click the toggle or the report name to collapse/expand the chart body
- **mo / yr / prev** — quick period switcher; reloads data from hledger
- **◕ / ▦** — toggle between doughnut and bar views (`*-pie` and `expenses` only); redraws without re-fetching
- **↺** — force reload from hledger

### Examples

````markdown
```chart
networth last2years
```

```chart
expenses-pie thismonth depth:3
```

```chart
expenses lastyear depth:2
```
````
